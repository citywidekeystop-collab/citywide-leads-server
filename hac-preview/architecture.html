Architecture & launch readiness

Technical design, ownership and acceptance criteria

Current state: static Render preview deployed from GitHub. The design is not the production HAC website. The backend design below is proposed, not installed.

Proposed production architecture

Use a server-rendered custom application on Render, with GitHub-managed source, PostgreSQL for durable content, a supported headless CMS or authenticated editorial service, approved object storage for documents, and a production authentication provider with MFA and role-based access. Confirm technology selection with HAC after discovery and security review. Separate staging and production.

Migration process

  1. Obtain HAC-authorized export of published pages, posts, taxonomies, PDF assets and redirect inventory. Exclude restricted board and member content unless separately authorized.
  2. Inventory URLs, source hashes and ownership; deduplicate and preserve dates, source links and taxonomies.
  3. Index accessible PDF text; remediate scanned or inaccessible documents and record exceptions. Check every destination and asset.
  4. Map former URLs to permanent new routes, validate redirects, compare inventory counts and obtain editorial signoff.

Analytics and privacy

Implement approved site-wide analytics in the production environment, respecting consent and retention policy. Track page views, search usage without sensitive queries, resource clicks and confirmed registrations or subscriptions through approved integrations. Establish a baseline and label click counts separately from conversions.

Accessibility and performance

Run automated accessibility tests and manual keyboard, screen-reader, zoom, mobile and contrast reviews against WCAG 2.2 AA. Test PDFs and media alternatives. Record issues and remediation. Measure Core Web Vitals on desktop and mobile; target LCP ≤2.5 s, INP ≤200 ms and CLS ≤0.1 at the 75th percentile. These are acceptance targets, not current measurements.

Security and operations

Configure HTTPS, least-privilege database and storage access, secure cookies, CSRF protection, input validation, MFA, rate limiting, audit logs, dependency updates and encrypted backups. Test restoration, deletion and account recovery. Use HAC-approved integrations only. Do not copy passwords or restricted documents into the preview.

Official requirements

HAC's 2026 website redesign RFP calls for accessible, responsive design, a staff-managed CMS, analytics, SEO, training and architectural documentation. The proposal deadline is December 15, 2026; planned kickoff February 1, 2027 and launch September 30, 2027. Production development requires agreement with HAC and cannot be certified from a prototype alone.

AI use and confidentiality

AI-assisted design, code development and content summarization were used for this independent preview. All public facts must receive human review. HAC requires AI-use disclosure and written approval before confidential data is entered into third-party tools.
